CORDIS · EVENTS

五种分派模式

模式是事件公共契约的一部分，@mode 标签由生成脚本校验。
模式是否 await顺序返回值短路方式典型事件
emit否注册序无不能短路session/event、agent/status、tools/result
parallel是并发无不能；有拒绝抛 AggregateErrorsession/flush（持久化栅栏）
serial是注册序逐个 await有第一个 isBailed 值agent/created、agent/turn-stopping
bail否注册序同步有第一个 isBailed 值internal/listener
waterfall取决于监听器外层先有省略 next() = 否决内置行为agent/pre-step、tools/pre-execute、llm/stream
// vendor/cordis/src/events.ts:234-243 waterfall(...args) { const cbs = this.dispatch('waterfall', args) const inner = args.pop() // 内置行为 const next = () => (cbs.shift() ?? inner)(...args) args.push(next); return next() }
选型口诀
要拦截点 → waterfall  ·  要检查点 → serial
要广播 → emit  ·  要"接管注册" → bail（internal/listener）
包装别人的决定要写 { ...decision, messages }，否则会丢掉下游声明的 startsRequestSeries。
